# iOS Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wrap the SvelteKit web build as an iOS Capacitor app sized for personal sideload — generate the Xcode project, regenerate iOS icon and splash assets from the existing `resources/` PNGs, and add safe-area CSS so notch + home indicator don't overlap content.

**Architecture:** Web changes land first (viewport meta, safe-area utilities, Capacitor config keys) and pass the existing pipeline unchanged. Then `bunx cap add ios` generates the Xcode project; `bunx @capacitor/assets generate --ios` produces icon/splash density variants from the same `resources/` PNGs Android uses.

**Tech Stack:** Capacitor 8 + `@capacitor/ios`, SvelteKit 2 + Tailwind v4 (`env(safe-area-inset-*)` utilities), Bun, CocoaPods (native dep manager — `brew install cocoapods` if missing).

**Spec:** [`2026-05-28-ios-shell.md`](../specs/2026-05-28-ios-shell.md)

## Notes for implementers

- The bun binary lives at `~/.bun/bin`. Prefix commands with `export PATH="$HOME/.bun/bin:$PATH"`.
- Pipeline per web task: `bun run typecheck && bun run lint && bun test && bun run e2e`. The web build is unchanged in behavior; `env()` insets resolve to 0 on Android/web so existing tests don't move.
- If `bun run e2e` fails on a 60s playwright `webServer` timeout, run `bun run build` first then `bun run e2e`.
- Pre-commit hook (lefthook) runs typecheck/lint/test/knip. Never `--no-verify`. Never push, never amend.
- Tasks 4–5 (iOS scaffold + assets) require macOS, Xcode command-line tools (`xcode-select --install` if missing), and CocoaPods (`brew install cocoapods`). If those aren't available, stop at Task 3, note the blocker in the report, and the user will run the remaining steps locally.

```html
  </body>
</html>
```

- [ ] **Step 2: Update the viewport meta tag and add the iOS status-bar meta**

Edit `src/app.html`. Make two changes inside `<head>`:

```diff
-    <meta name="viewport" content="width=device-width, initial-scale=1" />
+    <meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover" />
+    <meta name="apple-mobile-web-app-status-bar-style" content="default" />
```

`viewport-fit=cover` lets the web content draw under the iOS safe area (paired with `contentInset: 'never'` from Task 1, this is what makes `env(safe-area-inset-*)` return non-zero values on iPhone X+).

`apple-mobile-web-app-status-bar-style="default"` keeps the iOS status bar text dark on our light canvas (the alternative `black` value means dark *background*, which would clash).

### Task 3: Safe-area CSS on layout + skip link + cook dock

**Files:**
- Modify: `src/routes/+layout.svelte`
- Modify: `src/lib/ui/cook/CookTimerDock.svelte`

Bundled because they're all "honor iOS safe-area insets" changes and share a single commit message.

- [ ] **Step 1: Read the layout and dock**

Run:
```bash
cat src/routes/+layout.svelte && echo '---' && sed -n '195,205p' src/lib/ui/cook/CookTimerDock.svelte
```

You'll see the layout with `<main id="app-main">{@render children()}</main>` and a `Skip to content` link, plus the dock at `class="sticky bottom-0 z-30 bg-obsidian text-canvas px-4 py-2 flex items-center gap-4 overflow-x-auto relative"`.

- [ ] **Step 2: Update the layout's main wrapper and skip link**

Edit `src/routes/+layout.svelte`. Two changes:

a. **Skip link**: change `top-2` (or wherever the existing top utility is) to `top-[max(0.5rem,env(safe-area-inset-top))]`. Example:

```diff
 <a
   href="#app-main"
-  class="sr-only focus:not-sr-only fixed top-2 left-2 z-50 bg-canvas border border-obsidian px-3 py-2 rounded-sm text-sm focus:outline-2 focus:outline-ochre"
+  class="sr-only focus:not-sr-only fixed top-[max(0.5rem,env(safe-area-inset-top))] left-2 z-50 bg-canvas border border-obsidian px-3 py-2 rounded-sm text-sm focus:outline-2 focus:outline-ochre"
 >Skip to content</a>
```

b. **`<main>` element**: add `pt-[env(safe-area-inset-top)] pb-[env(safe-area-inset-bottom)]` to its class. The current `<main>` likely has no `class` attribute (just `id="app-main"`); add the class:

```diff
- <main id="app-main">
+ <main
+   id="app-main"
+   class="pt-[env(safe-area-inset-top)] pb-[env(safe-area-inset-bottom)]"
+ >
   {@render children()}
 </main>
```

If the existing `<main>` already has classes, append the two utilities to its class string.

- [ ] **Step 3: Update the cook timer dock**

Edit `src/lib/ui/cook/CookTimerDock.svelte`. Find the sticky dock `<div>` (line ~200, class begins with `sticky bottom-0 …`) and append `pb-[env(safe-area-inset-bottom)]`:

```diff
- class="sticky bottom-0 z-30 bg-obsidian text-canvas px-4 py-2 flex items-center gap-4 overflow-x-auto relative"
+ class="sticky bottom-0 z-30 bg-obsidian text-canvas px-4 py-2 flex items-center gap-4 overflow-x-auto relative pb-[env(safe-area-inset-bottom)]"
```

Note: the dock already had a `py-2` (2 * 0.5rem = 16px). The new `pb-[env(...)]` is a one-direction override — Tailwind's `pb-*` wins over `py-*`'s bottom on specificity (later in the class string and more specific selector). Visual effect on iPhone: the dock keeps its 16px top padding and gains a bottom padding equal to the safe-area inset, lifting timer content above the home indicator.


Expected: green. On Android/web, `env(safe-area-inset-*)` returns 0, so layout is unchanged.
