# A11y Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve the six highest-impact accessibility issues from the audit by changing primitives, theme tokens, and per-route markup so the fix radiates across the app.

**Architecture:** Six independent fixes ordered so each commit leaves the app green. Theme + Button + anchor focus rings ship first (no consumer changes); then layout `<main>` wrapper enables the Dialog focus trap; then FormError primitive lands with its first consumer and migrations follow one file at a time; finally per-route `<title>` blocks land in a single coordinated commit.

**Tech Stack:** SvelteKit 2, Svelte 5 (runes, snippets, `$effect`), Tailwind v4 (`@theme`, `@layer components`), Bun + `bun:test`, Playwright e2e.

**Spec:** [`2026-05-22-a11y-phase-1.md`](../specs/2026-05-22-a11y-phase-1.md)

## Notes for implementers

- The bun binary lives at `~/.bun/bin`. Prefix commands with `export PATH="$HOME/.bun/bin:$PATH"` or include the export inline.
- Migrations are visual/structural changes. **No new unit tests** for this work. Validation per task is `bun run typecheck && bun run lint && bun test && bun run e2e`. All four must remain green.
- The pre-commit hook (lefthook) runs typecheck/lint/test/knip. Knip rejects unused source files — that's why the new `FormError` primitive must ship together with its first consumer.
- User preference: never push, never `--amend`, never `--no-verify`. Each task ends at `git commit`.

### Task 5: Dialog focus management

**Files:**
- Modify: `src/lib/ui/primitives/Dialog.svelte`

- [ ] **Step 1: Read the current Dialog.svelte**

Run: `cat src/lib/ui/primitives/Dialog.svelte`

You'll see the existing `<svelte:window onkeydown>` Escape handler and the `<div role="dialog" tabindex="-1">` backdrop. We're adding a focus-management `$effect`.

- [ ] **Step 2: Add the focus-management `$effect` to the script block**

After the line `const sizeClass = $derived(SIZE_CLASS[size]);` and before the `CARD_BASE` constant, add this effect. (Imports stay at the top; this lives in the runtime block.)

```ts
  let previouslyFocused: HTMLElement | null = null;
  let dialogEl = $state<HTMLDivElement | null>(null);

  $effect(() => {
    if (!open) return;

    previouslyFocused = document.activeElement as HTMLElement | null;
    const main = document.getElementById('app-main');
    main?.setAttribute('inert', '');
    // Move focus into the dialog. Defer one microtask so the dialog DOM is mounted.
    queueMicrotask(() => dialogEl?.focus());

    return () => {
      main?.removeAttribute('inert');
      previouslyFocused?.focus?.();
      previouslyFocused = null;
    };
  });
```

Note: `dialogEl` uses `$state()` because we bind to it via `bind:this`. `previouslyFocused` is a plain `let` because we never want the template to react to it.

- [ ] **Step 3: Bind `dialogEl` to the role=dialog div**

Find the existing `<div ... role="dialog" aria-modal="true" ... tabindex="-1">` and add `bind:this={dialogEl}`:

```diff
  <div
+   bind:this={dialogEl}
    class="fixed inset-0 bg-obsidian/40 flex items-center justify-center z-50"
    onclick={backdropClick}
    onkeydown={(e) => e.key === 'Escape' && close()}
    role="dialog"
    aria-modal="true"
    aria-labelledby={headingId}
    tabindex="-1"
  >
```
