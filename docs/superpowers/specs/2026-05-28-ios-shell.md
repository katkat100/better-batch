# iOS shell: Capacitor scaffold + safe-area handling

**Status:** Design approved 2026-05-28.
**Owner:** Katie.

## Summary

Wrap the SvelteKit web build as a native iOS app via Capacitor, sized
for personal sideload (no Apple Developer account required for the
initial setup). Generate the Xcode project, regenerate icon and
splash assets for iOS densities from the existing `resources/`
sources, and add safe-area inset handling so the home indicator and
notch don't overlap our content.

The bundle id and app name match Android (`io.github.katkat100.betterbatch`,
"Better Batch"). Universal device family (iPhone + iPad) per the
existing responsive layout.

## Motivation

The user wants to install Better Batch on their iPhone. The web build
is already SPA-friendly and `@capacitor/local-notifications` works on
iOS — what's missing is the iOS native shell, icon/splash assets,
and CSS handling for the iOS-specific safe-area insets (notch + home
indicator). This spec covers the minimum needed to build, sign with a
free personal Apple team, and run on a connected device.

App Store distribution is explicitly out of scope (it requires a
paid Apple Developer account, additional metadata, and Apple review
that takes weeks).

## Behavior

### iOS scaffold

Add the iOS Capacitor runtime:

```bash
bun add @capacitor/ios
bunx cap add ios
```

`cap add ios` generates `ios/App/` containing the Xcode project,
runs `pod install` to fetch native dependencies (CocoaPods must be
installed locally — `brew install cocoapods`), and wires the iOS
project to consume `webDir: 'build'` for the SvelteKit static
output.

The bundle identifier is read from `capacitor.config.ts`'s `appId`
(`io.github.katkat100.betterbatch`) and the display name from
`appName` ("Better Batch") — both match Android.

### Capacitor config additions

Edit `capacitor.config.ts` to add iOS-specific keys and tighten the
launch transition on both platforms:

```ts
import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  appId: 'io.github.katkat100.betterbatch',
  appName: 'Better Batch',
  webDir: 'build',
  ios: {
    contentInset: 'never',
    backgroundColor: '#F5F2ED'
  },
  android: {
    backgroundColor: '#F5F2ED'
  }
};

export default config;
```

- `contentInset: 'never'` tells WKWebView to draw under the safe area
  so our CSS `env(safe-area-inset-*)` returns real pixel values.
  Without this, iOS letterboxes the WebView at the safe area and
  the env() insets evaluate to zero.
- `backgroundColor: '#F5F2ED'` matches our canvas token. Used as the
  WebView background while the web bundle is loading so the
  splash-to-content transition doesn't flash white. The Android key
  is the same change for parity (no harm; Android renders behind the
  WebView until our app paints).

### Asset generation

```bash
bunx @capacitor/assets generate --ios
```

Reads the existing `resources/icon.png`, `resources/icon-foreground.png`,
`resources/icon-background.png`, and `resources/splash.png` (all four
PNG sources are checked in already from the Android setup).
Generates:

- `ios/App/App/Assets.xcassets/AppIcon.appiconset/` — every required
  size (20pt, 29pt, 40pt, 60pt @ 1x/2x/3x; 76pt, 83.5pt @ 1x/2x;
  1024pt App Store marketing icon).
- `ios/App/App/Assets.xcassets/Splash.imageset/` — the launch image
  used by `Splash.storyboard`.

The `splash.png` source already has `#F5F2ED` baked in from the
Android round (commit `f9d3460`), so the iOS splash will show the BB
logo on canvas — no flash of white.

### Viewport meta + status bar (`src/app.html`)

Two changes:

1. **`viewport-fit=cover`** so iOS draws under the safe area:
   ```html
   <meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover" />
   ```

2. **Status-bar appearance** — keep the iOS status bar text dark on
   our light canvas:
   ```html
   <meta name="apple-mobile-web-app-status-bar-style" content="default">
   ```
   `default` means dark text content on a light background, which
   matches the canvas background showing behind it.

### Safe-area CSS

Tailwind v4 supports `env()` in arbitrary values (`pt-[env(safe-area-inset-top)]`).
We apply insets at three sites:

1. **Layout wrapper** (`src/routes/+layout.svelte`):
   ```svelte
   <main
     id="app-main"
     class="pt-[env(safe-area-inset-top)] pb-[env(safe-area-inset-bottom)]"
   >
     {@render children()}
   </main>
   ```
   On Android the env() values are zero, so this is a no-op. On
   iPhone X+ the top inset clears the notch and the bottom inset
   clears the home indicator.

2. **Skip-to-content link** (also `+layout.svelte`):
   ```svelte
   <a
     href="#app-main"
     class="sr-only focus:not-sr-only fixed top-[max(0.5rem,env(safe-area-inset-top))] left-2 z-50 …"
   >Skip to content</a>
   ```
   Uses `max(0.5rem, env(...))` so it stays at least 8px below the
   top edge even on devices with no inset.

3. **Sticky cook timer dock** (`src/lib/ui/cook/CookTimerDock.svelte`):
   Append `pb-[env(safe-area-inset-bottom)]` to the existing dock
   `<div>`'s class string so timers don't sit behind the home
   indicator.

### iOS-only quirks we explicitly do NOT handle

- **Swipe-from-left-edge back gesture**: WKWebView handles this
  natively for history navigation. No app-side wiring needed; the
  Capacitor `App.backButton` listener we added for Android is a
  no-op on iOS, which is correct.
- **iOS keyboard layout-viewport shift**: Capacitor's default WebView
  config handles this well; if a specific input gets visually
  clipped behind the keyboard we'll revisit.
- **Double-tap zoom**: Tailwind's `touch-manipulation` utility would
  disable it but we're not adding that pre-emptively. Investigate if
  reported.

## Architecture

### Files added

- `ios/` — the entire generated Xcode project, including:
  - `ios/App/App.xcworkspace/` — the workspace Xcode opens.
  - `ios/App/App.xcodeproj/` — the project file.
  - `ios/App/App/` — Swift sources (`AppDelegate.swift`, `Info.plist`, `Assets.xcassets`, storyboards).
  - `ios/App/Podfile` and `ios/App/Podfile.lock` — CocoaPods deps.
  - `ios/.gitignore` — excludes `Pods/` and `DerivedData/`.

  Generated directories like `ios/App/Pods/` and `ios/build/` are gitignored.

### Files modified

- `package.json`, `bun.lock` — `@capacitor/ios` dep.
- `capacitor.config.ts` — `ios.contentInset`, `ios.backgroundColor`, `android.backgroundColor`.
- `src/app.html` — viewport `viewport-fit=cover` + status-bar meta.
- `src/routes/+layout.svelte` — safe-area inset utilities on `<main>` and skip link.
- `src/lib/ui/cook/CookTimerDock.svelte` — `pb-[env(safe-area-inset-bottom)]`.

### Files NOT modified

- Existing Android files (`android/`) — untouched. The shared
  `resources/` PNG sources drive both platforms.
- `tests/e2e/*` — Playwright runs against a web browser, not the iOS
  WebView. No new e2e tests; iOS verification is manual via Xcode.

## Testing

This work is primarily build/config — no new runtime logic. Validation:

1. **Pipeline**: `bun run typecheck && bun run lint && bun test && bun run e2e` must stay green across every commit. The web build is unchanged in behavior; the safe-area CSS adds `0px` insets on Android and web, so existing tests don't move.

2. **Manual iOS verification on a Mac with Xcode**:
   1. `bunx cap sync ios` — copies the web build into the Xcode project.
   2. `bunx cap open ios` — opens `ios/App/App.xcworkspace` in Xcode.
   3. In Xcode: select the **App** target → **Signing & Capabilities** → choose your personal Apple team (sign in with Apple ID if needed; no developer account required for personal sideload).
   4. Plug in an iPhone via USB and select it as the run destination.
   5. Press Cmd+R to build and run. The first install on a fresh device may prompt the user to trust the developer profile under iOS Settings → General → VPN & Device Management.
   6. Verify:
      - Launch shows the canvas-colored splash with the BB logo (no white flash).
      - Status bar reads as dark icons on the light background.
      - Home page renders below the notch (recipe list visible, no clipping).
      - On a recipe with active timers in the cook view, the dock sits above the home indicator (no overlap).
      - Swipe-from-left-edge gesture pops route history (recipe detail → home).
      - Create a recipe → batch → cook → end cook → verify the full happy path works.

3. **Build numbers and versioning**: the default Xcode-generated `Info.plist` has version `1.0` and build `1`. Leave those alone — they only matter for App Store distribution.

## Out of scope

- **Apple Developer account / paid program** — required for TestFlight and App Store. Personal sideload uses the free Apple team cert, which expires after 7 days but can be re-signed via Xcode any time.
- **App Store Connect setup** — bundle metadata, screenshots, privacy nutrition labels, marketing copy, App Review.
- **TestFlight beta distribution** — needs the paid program plus App Store Connect.
- **APNs push notifications** — `@capacitor/local-notifications` (already installed) covers local cook-timer alerts; remote push would need an Apple Push Notification certificate and server-side infrastructure that doesn't exist.
- **iOS-specific Capacitor plugins** like Live Activities, App Clips, or widgets.
- **Automated iOS CI/CD** — Fastlane or `xcodebuild` automation. Future work.
- **iPad-specific multitasking polish** — Split View, Slide Over, Stage Manager. The responsive layout will adapt naturally via Tailwind's `md:` / `lg:` breakpoints; specific polish (e.g., Sidebar layouts on iPad) is future work.
