# A11y Phase 3: deferred polish

**Status:** Design approved 2026-05-22.
**Owner:** Katie.

## Summary

Close out the remaining items from the original a11y audit. Four
deliverables:

1. Drop `role="dialog"` from the inconsistency popover (it's a popover, not a modal).
2. Drop `role="menu"` / `role="menuitem"` from the MultiplierToggle ⋯ dropdown (YAGNI; we don't implement arrow-key navigation).
3. Bump `.text-placeholder` opacity from `text-obsidian/40` to `text-obsidian/60` for WCAG AA contrast.
4. Migrate seven hand-rolled "no data yet" empty-state placeholders to `.text-placeholder`, and bump remaining hard-coded `text-obsidian/40` on body text to `/60`. Decorative separator glyphs stay at `/40`.

## Deferred (still)

## Behavior

### 1. Drop `role="dialog"` from inconsistency popover

`src/lib/ui/BatchDetail.svelte` — the inconsistency popover element:

```diff
  <span
-     role="dialog"
      id="inconsistency-popover"
      class="absolute left-0 top-full mt-1 z-10 w-72 …"
      data-testid="inconsistency-popover"
  >
```

The trigger button already declares the popover via `aria-expanded={popoverOpen}` + `aria-controls="inconsistency-popover"`, which is enough for screen readers to announce the relationship. The popover is short content next to its trigger, not a modal — `role="dialog"` would carry incorrect expectations (modal semantics, focus trap, etc.).

### 2. Drop `role="menu"` from MultiplierToggle AND BatchDetail more-actions

Both popovers carry `role="menu"` / `aria-haspopup="menu"` without implementing the arrow-key navigation that the ARIA menu contract requires. Same fix to both: drop the roles. They become plain vertical button groups.

#### 2a. MultiplierToggle

`src/lib/ui/MultiplierToggle.svelte`:

```diff
  <div
      id="multiplier-more-menu"
      class="absolute top-full right-0 mt-1 …"
-     role="menu"
      data-testid="multiplier-more-menu"
  >
    {#each menuValues as v (v)}
      <button
        type="button"
        class="…"
-       role="menuitem"
        onclick={() => pick(v)}
        data-testid="multiplier-option"
        data-value={v}
      >{fmt(v)}</button>
    {/each}
  </div>
```

The ARIA menu pattern requires arrow-key navigation between items (`↑`/`↓` to move, `Home`/`End` to jump to ends). We don't implement that — and for a popover with 2-3 plain buttons, the pattern is overkill. Screen readers announce each button individually after dropping the roles, which is the correct experience here.

Also drop `aria-haspopup="menu"` on the ⋯ trigger:

```diff
  <button
      …
-     aria-haspopup="menu"
      aria-expanded={menuOpen}
      aria-controls="multiplier-more-menu"
      …
  >⋯</button>
```

`aria-controls` + `aria-expanded` already conveys the popup relationship without committing to the menu pattern.

#### 2b. BatchDetail more-actions menu

`src/lib/ui/BatchDetail.svelte`:

```diff
  <button
      …
      aria-label="More actions"
-     aria-haspopup="menu"
      aria-expanded={moreOpen}
      aria-controls="more-actions-menu"
      data-testid="more-actions-btn"
  >…</button>
```

```diff
  <div
      id="more-actions-menu"
-     role="menu"
      class="absolute right-0 top-full mt-1 w-44 …"
      data-testid="more-actions-menu"
  >
```

The menu items inside (`<Button variant="menuitem">`) are already real buttons — they don't carry `role="menuitem"` (that role is only on MultiplierToggle's items), so nothing to remove on the children side here.

### 3. Bump `.text-placeholder` contrast

`src/app.css`:

```diff
  .text-placeholder {
-     @apply text-sm text-obsidian/40 italic;
+     @apply text-sm text-obsidian/60 italic;
  }
```

`#1A1A1A` at 60% opacity on `#F5F2ED` measures ~5.1:1 — passes AA for body text. The italic styling preserves the "subdued / placeholder" visual intent. Phase 1 had a consumer count of zero for this utility; Task 4 below adds seven consumers.

### 4. Migrate empty-state placeholders + bump remaining `/40` body text

A grep of `src/lib/ui` for `text-obsidian/40` returns ~25 hits. They fall into three categories:

**A. Italic empty-state placeholders** — migrate from hand-rolled `text-sm text-obsidian/40 italic` to `class="text-placeholder"`. Seven sites:

- `src/lib/ui/IngredientDiff.svelte:24` — "No ingredients to compare."
- `src/lib/ui/StepsList.svelte:25` — "No steps recorded."
- `src/lib/ui/IngredientList.svelte:40` — "No ingredients recorded."
- `src/lib/ui/StepsDiff.svelte:22` — "No steps to compare."
- `src/lib/ui/BatchPickerDropdown.svelte:39` — italic empty state inside the picker (preserve `px-3 py-3` layout extras: `class="text-placeholder px-3 py-3"`)
- `src/lib/ui/cook/CookStepList.svelte:44` — italic placeholder inside the cook list (preserve `px-4 py-3` extras)
- `src/lib/ui/BatchDetail.svelte:350` — italic placeholder inside the batch detail view

For each, replace `class="text-sm text-obsidian/40 italic …"` with `class="text-placeholder …"` (keep any non-color/non-italic extras).

**B. Body text using `text-obsidian/40`** — bump to `/60`. The audit's WCAG concern applies here too. Five sites:

- `src/lib/ui/BatchDetail.svelte:156` — "Archived" status text (`text-[11px] uppercase tracking-wider text-obsidian/40 mt-1` → `… text-obsidian/60 …`)
- `src/lib/ui/NotecardCard.svelte:47` — recipe last-cooked label (the not-cooked branch only; keep the cooked branch's `text-juniper`)
- `src/lib/ui/MergeIngredientRow.svelte:39, 41` — "unch" / "in result" labels (text-[9px] uppercase)
- `src/lib/ui/MergeStepRow.svelte:36, 38` — same pattern
- `src/lib/ui/MergePicker.svelte:173, 183` — "Result: N ingredients/steps" counts (text-[10px])
- `src/routes/recipes/[id]/+page.svelte:196` — recipe-page paragraph (description) (`text-sm text-obsidian/40` → `text-sm text-obsidian/60`)
- `src/lib/ui/BatchEditor.svelte:463` — step number prefix `{i+1}.` (font-mono text-xs)

**C. Decorative separator glyphs** — keep `text-obsidian/40`. Not body text; AA contrast doesn't apply to non-text decoration:

- `src/lib/ui/BatchDetail.svelte:363` — `·` separator
- `src/lib/ui/MergeIngredientRow.svelte:46` — `→` separator
- `src/lib/ui/CompareView.svelte:29` — `↔` separator
- `src/lib/ui/MergePicker.svelte:133, 135` — `+`, `→` separators
- `src/lib/ui/cook/CookTopBar.svelte:36` — `·` separator
- `src/lib/ui/StepsDiff.svelte:27` — diff prefix glyph (`+` / `-` markers)
- `src/lib/ui/VariableDiffTable.svelte:34` — return value (string, not a class on a real element) — leave as is.

**D. VariableDiffTable special case** — `src/lib/ui/VariableDiffTable.svelte:34` returns `'text-obsidian/40'` as the delta color when there's no change. This colors a row's text in the diff table to mute "no change" rows. It's body text (delta values), so bump to `/60`:

```diff
- if (row.delta === null || row.delta === 0) return 'text-obsidian/40';
+ if (row.delta === null || row.delta === 0) return 'text-obsidian/60';
```
