# A11y Phase 2: structural fixes + IconButton

**Status:** Design approved 2026-05-22.
**Owner:** Katie.

## Summary

Resolve the remaining audit items beyond the Phase 1 round. Eight
deliverables:

1. **CookStepRow** stops wrapping a nested `<button>` inside a `<label>`.
2. **BatchGraph** SVG nodes get real HTML `<button>` semantics via `<foreignObject>`.
3. **Click-outside overlays** in BatchDetail / MultiplierToggle / CookTimerDock leave the keyboard tab order.
4. **BatchDetail** ESC handler closes the Compare/Merge picker overlays.
5. **Layout** ships a skip-to-content link.
6. **IconButton primitive** enforces 44×44 hit areas and a required `aria-label` for every icon-only glyph.
7. **ARIA-controls** wired on the three remaining popover triggers.
8. **CookTimerDock** `animate-pulse` honors `prefers-reduced-motion`.

## Deferrals from the audit

- **Field aria-describedby / aria-invalid** — no current consumer passes `Field error={…}`. Form errors all flow through the form-level `FormError` primitive instead. Add the threading when a real consumer needs it.
- **text-obsidian/40 site bumps** — per-site judgment calls (e.g. "Archived" status text, "No data yet" placeholders). Not a primitive-level fix; leave for a future polish pass.
- **MultiplierToggle `role="menu"` arrow-key navigation** — either implement roving tabindex or drop the role. Punted; not a regression from the audit, just an unfinished pattern.
- **BatchDetail popover `role="dialog"`** — should be removed (it's a popover, not a dialog). Punted as a small code-only follow-up.

## Behavior

### 1. CookStepRow — lift timer buttons out of `<label>`

Current structure (invalid HTML):

```svelte
<li>
  <label class="...">
    <Checkbox … />
    <div class="flex-1 flex flex-col gap-1">
      <p>{index + 1}. {#each segments}<button>{seg.text}</button>{/each}</p>
    </div>
  </label>
</li>
```

The `<label>` wraps a `<button>` (the timer trigger), which is not
permitted HTML and breaks screen-reader semantics. The current code
patches over it with `e.preventDefault()` to stop label-toggle
bubbling.

New structure:

```svelte
<li>
  <div class="flex gap-3 px-4 py-3 hover:bg-drafting/20">
    <Checkbox … aria-labelledby={`cook-step-text-${index}`} />
    <div class="flex-1 flex flex-col gap-1">
      <p id={`cook-step-text-${index}`} class="…">
        {#each segments}…<button>{seg.text}</button>…{/each}
      </p>
      <!-- uses list -->
    </div>
  </div>
</li>
```

Changes:
- `<label>` becomes `<div>`. Row no longer is a single click-to-toggle target.
- Checkbox's accessible name comes from `aria-labelledby` pointing at the step text `<p>`.
- Timer `<button>` elements are now plain semantic buttons; their `e.preventDefault()` workaround is no longer needed but can stay (harmless).
- `cursor-pointer` is removed from the wrapper since clicking the text no longer toggles the checkbox.

UX impact: clicking the step text no longer toggles the checkbox. Users tap the checkbox directly. This matches every other checkbox+label-with-interactive-content pattern in the codebase.

### 2. BatchGraph — `<foreignObject>` per node

Each SVG `<g>` node currently has `role="button" tabindex="0"
aria-label="…" aria-pressed onclick onkeydown`. Screen readers handle
this inconsistently (some announce as button, some as graphic).

Fix: wrap each node's interactive surface in a `<foreignObject>` that
contains a real HTML `<button>`. The `<g>` keeps its SVG decoration
(circles, text). The button absorbs all interactive behavior.

```svelte
<g transform="translate({n.x + PAD},{n.y + PAD})">
  <foreignObject x={-NODE_R - 4} y={-NODE_R - 4} width={(NODE_R + 4) * 2} height={(NODE_R + 4) * 2}>
    <button
      type="button"
      aria-label="Select batch {batch.label} ({batch.status})"
      aria-pressed={isSelected}
      onclick={() => onSelect(n.id)}
      class="w-full h-full bg-transparent border-0 p-0 cursor-pointer focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ochre rounded-full"
      data-testid="batch-node"
      data-batch-id={n.id}
    ></button>
  </foreignObject>
  <!-- existing SVG circles + text + warning -->
</g>
```

The button stays empty visually — the SVG circles + text rendered as
siblings of the foreignObject do all the painting. The button's hit
area is sized to cover the node circle plus a small margin; the label
text below is NOT inside the click area (matches current behavior —
the label is decoration, not part of the click target).

`<foreignObject>` has solid modern-browser support (Chromium, Firefox,
WebKit). Capacitor Android (Chromium WebView) handles it correctly.

### 3. Click-outside overlays — leave the tab order

Three sites use a full-screen invisible button as click-outside catcher:

- `src/lib/ui/BatchDetail.svelte` — more-actions overlay (`fixed bg-transparent inset-0 z-20`)
- `src/lib/ui/MultiplierToggle.svelte` — ⋯ menu overlay (`fixed inset-0 z-10 bg-transparent`)
- `src/lib/ui/cook/CookTimerDock.svelte` — manual timer overlay (`fixed inset-0 z-40 bg-transparent`)

Each is a focusable `<button>` with an `aria-label` like "close menu",
which puts a phantom button in the keyboard tab order. Each component
already has a `<svelte:window onkeydown>` ESC handler.

Fix: add `tabindex="-1" aria-hidden="true"` to each overlay button.
That removes them from both the keyboard tab order AND the screen
reader tree. Mouse click-outside still works.

### 4. BatchDetail ESC handler

`src/lib/ui/BatchDetail.svelte:63-67`:

```diff
function onWindowKeydown(e: KeyboardEvent) {
    if (e.key !== 'Escape') return;
    if (popoverOpen) popoverOpen = false;
    if (moreOpen) moreOpen = false;
+   if (compareOpen) compareOpen = false;
+   if (mergeOpen) mergeOpen = false;
}
```

That's it. Compare/Merge pickers now close on ESC like the other popovers.

### 5. Skip-to-content link

`src/routes/+layout.svelte`:

```svelte
<a
  href="#app-main"
  class="sr-only focus:not-sr-only fixed top-2 left-2 z-50 bg-canvas border border-obsidian px-3 py-2 rounded-sm text-sm focus:outline-2 focus:outline-ochre"
>Skip to content</a>

<main id="app-main">
  {@render children()}
</main>
```

Tailwind v4 doesn't ship `.sr-only` by default. Add it to the
`@layer components` block in `app.css`:

```css
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border-width: 0;
}
.focus\:not-sr-only:focus,
.focus\:not-sr-only:focus-visible {
  position: static;
  width: auto;
  height: auto;
  padding: 0;
  margin: 0;
  overflow: visible;
  clip: auto;
  white-space: normal;
}
```

The link target is `#app-main` (the `<main>` landmark added in Phase 1).
Pressing Tab on a fresh page focuses the skip link first; pressing
Enter jumps focus past the page chrome into the main content.

### 6. IconButton primitive

New file `src/lib/ui/primitives/IconButton.svelte`:

```svelte
<!-- src/lib/ui/primitives/IconButton.svelte -->
<script lang="ts">
  import type { Snippet } from 'svelte';

  let {
    'aria-label': ariaLabel,
    onclick,
    disabled = false,
    class: extraClass = '',
    children,
    ...rest
  }: {
    'aria-label': string;
    onclick?: (e: MouseEvent) => void;
    disabled?: boolean;
    class?: string;
    children: Snippet;
    [key: string]: unknown;
  } = $props();
</script>

<button
  type="button"
  aria-label={ariaLabel}
  {disabled}
  {onclick}
  class="p-2.5 leading-none text-obsidian/60 hover:text-obsidian disabled:opacity-50 disabled:cursor-not-allowed focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ochre {extraClass}"
  {...rest}
>
  {@render children()}
</button>
```

The TypeScript type forces `aria-label` to be passed — every icon-only
button gets a non-empty accessible name. The default color
(`text-obsidian/60`) and hover (`text-obsidian`) match the existing
ghost-button pattern for muted icon buttons.

**Migration list:**

- `src/lib/ui/BatchEditor.svelte` — 4 icon-only buttons:
  - move-up `▲` per ingredient row
  - move-down `▼` per ingredient row
  - remove `×` per ingredient row
  - remove `×` per step row
- `src/lib/ui/cook/CookTimerDock.svelte` — 1 button:
  - remove timer `×`
- `src/lib/ui/cook/CookQuickNoteFab.svelte` — 2 buttons:
  - edit note (link-styled but icon-y in mobile)
  - delete note
- `src/lib/ui/EditVariablesDialog.svelte` — 1 button:
  - remove variable `×`
- `src/lib/ui/UsesEditor.svelte` — 1 icon button (remove-use `×`). Implementer should grep for the existing inline `×` button(s) in this file and migrate any that match the icon-only pattern.

Each migration replaces the inline `<button class="…px-…">×</button>` with `<IconButton aria-label="…">×</IconButton>`. Extra classes (e.g. positioning, color overrides) flow through the `class` prop.

**Excluded from this primitive:**

- The ⚠ inconsistency badge in `BatchDetail.svelte` — it's a popover trigger with extra state (`aria-expanded`, `aria-controls`, custom positioning). Leave it inline.
- Any icon-only button inside the BatchGraph foreignObject — those are handled by Task 2.

### 7. ARIA-controls on popover triggers

- **BatchDetail inconsistency popover.** Give the `<span role="dialog">` (which will be downgraded to `<div>` in a future round) `id="inconsistency-popover"`. Add `aria-controls="inconsistency-popover"` to the triggering ⚠ button.
- **BatchDetail more-actions menu.** Give the menu `<div>` `id="more-actions-menu"`. Add `aria-controls="more-actions-menu"` + `aria-haspopup="menu"` to the … trigger button.
- **MultiplierToggle ⋯ menu.** Give the menu `<div>` `id="multiplier-more-menu"`. Add `aria-controls="multiplier-more-menu"` to the ⋯ trigger (it already has `aria-haspopup="menu"` and `aria-expanded`).
- **CookTimerDock manual timer popover.** Give it `id="manual-timer-popover"`. Add `aria-controls` to the "+ Manual" trigger.

These IDs are scoped per-component instance. Because none of these components are rendered multiple times on the same page in practice, hard-coding the IDs is safe. If that changes later, switch to a `crypto.randomUUID()`-style auto-id.

### 8. `motion-safe:` on `animate-pulse`

`src/lib/ui/cook/CookTimerDock.svelte:201` (or wherever the pulsing class lives):

```diff
- class="… animate-pulse"
+ class="… motion-safe:animate-pulse"
```

Users with `prefers-reduced-motion: reduce` no longer see the pulse animation. The finished-timer state still reads as ochre-colored text; the visual cue is intact.

## Testing

This is a primarily visual + structural change. No new unit or e2e
tests are added. Validation per task: `bun run typecheck && bun run
lint && bun test && bun run e2e`. All four stay green.

Manual a11y spot checks (run once at the end of Phase 2):

1. Tab through a fresh page. The first focusable element is the skip link.
2. Activate the skip link with Enter. Focus jumps inside `<main>`.
3. Open BatchDetail, hit ESC with the more-actions, compare, or merge picker open. All close.
4. Tab around the recipe page. Verify the ⋯-menu / inconsistency-popover / manual-timer-popover overlays do not show up in the tab order anymore.
5. Mobile-emulator: confirm the `×` / `▲` / `▼` buttons in the batch editor are at least 44×44 hit area.
6. Tab into the batch graph: each node receives focus via its `<foreignObject>` button. Enter selects.
7. Set `prefers-reduced-motion: reduce` in browser dev tools; start a cook timer. The finished-timer cell does not pulse.
