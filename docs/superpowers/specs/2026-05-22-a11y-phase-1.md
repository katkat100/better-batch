# A11y Phase 1: cross-cutting fixes

**Status:** Design approved 2026-05-22.
**Owner:** Katie.

## Summary

Resolve the six highest-impact accessibility issues found in the audit
in a single coordinated round. Each fix touches many call sites at
once by changing a primitive, a theme token, or by adding one piece of
markup per route.

Concrete deliverables:

1. `Dialog` primitive traps focus with `inert` and restores focus on close.
2. `Button` primitive gains a visible focus ring; the few anchor-styled-as-button strings get the same treatment.
3. `--color-ochre` darkens globally (#A65D39 → #8E4A2A) for WCAG AA contrast on `--color-canvas`.
4. `.text-caption` and `.text-kicker` bump opacity from `text-obsidian/50` to `text-obsidian/70` for the same reason.
5. New `FormError` primitive renders the error message inside `role="alert" aria-live="polite"`. Seven dialogs/editors switch to it.
6. Every route gets a meaningful `<title>` via `<svelte:head>`.

## Motivation

The audit ([2026-05-22 a11y audit](../../#)) found 38+ issues. Five
patterns account for most of the user-facing impact: dialogs that
release keyboard focus into an inert page, buttons that show no focus
ring, low-contrast small text using `.text-caption` / `.text-kicker`,
form errors that screen readers don't announce, and pages that all
read as "Better Batch" to assistive tech. The remaining audit items
(touch-target sizing, IconButton primitive, click-outside overlay
cleanup, CookStepRow nested-button-in-label, etc.) are deferred to a
later round so this one stays bounded.

## Behavior

### 1. Dialog focus management

`src/lib/ui/primitives/Dialog.svelte` adds an `$effect` that runs when
`open` changes:

- **On open**:
  1. Save `document.activeElement` as `previouslyFocused`.
  2. Set the `inert` attribute on the page's `<main>` wrapper (the
     route-level wrapper added in step 6). Inert removes the page from
     the keyboard tab order and from screen-reader navigation, so
     tabbing inside the dialog cannot reach anything outside.
  3. After the next microtask (or `tick()`), move focus to the dialog
     container itself (`tabindex="-1"` already on the role=dialog div).
     If the dialog body contains a form input, the existing
     auto-focus effects in consumer components (e.g. `nameEl.focus()`
     in `NewRecipeDialog`) still take precedence — they run after the
     dialog mounts.

- **On close**:
  1. Remove `inert` from the wrapper.
  2. Restore focus: `previouslyFocused?.focus?.()`.
  3. Null out `previouslyFocused`.

If the same `<main>` wrapper would be inerted by two simultaneously
open dialogs, this is fine — `inert` is a boolean attribute. The
effect's cleanup function handles teardown when `open` flips false or
the component unmounts.

### 2. Button focus ring

`src/lib/ui/primitives/Button.svelte` adds to its `COMMON` class
string:

```
focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ochre
```

`focus-visible` (not `focus`) means the ring shows on keyboard focus
but not on mouse clicks, matching standard browser-button behavior.
The ochre outline reads on both the dark obsidian variants and the
canvas background. Disabled buttons still get the ring on focus,
which is fine — disabled-and-focusable is intentional (a screen
reader user can still navigate to learn why it's disabled).

For the five raw anchor-styled-as-button strings the audit flagged —
`BatchDetail.svelte` "+ New Batch" / "Cook" / Edit / Mark as Cooked
anchors, and `routes/+page.svelte`'s recipe-list call-to-action — we
append the same three `focus-visible:*` classes. We do NOT extract
them to a `.btn-focus` component class; five sites is below the
threshold from the prior style-deduplication round.

### 3. Color token: darken ochre

`src/app.css`:
```diff
- --color-ochre: #A65D39;
+ --color-ochre: #8E4A2A;
```

WCAG AA requires 4.5:1 for normal text and 3:1 for large/UI components.
`#8E4A2A` on `#F5F2ED` measures ~5.6:1 — passes for body text. This
darkening affects every ochre use site: borders, badges, focus rings,
text. The brand identity stays cohesive because all surfaces shift by
the same delta. Expect a slightly deeper rust tone across the app.

### 4. Text utility class opacity bumps

`src/app.css` `@layer components`:
```diff
  .text-caption {
-   @apply text-[11px] uppercase tracking-wider text-obsidian/50;
+   @apply text-[11px] uppercase tracking-wider text-obsidian/70;
  }
  .text-kicker {
-   @apply text-[10px] uppercase tracking-wider text-obsidian/50;
+   @apply text-[10px] uppercase tracking-wider text-obsidian/70;
  }
```

`#1A1A1A` at 70% opacity on `#F5F2ED` measures ~7.0:1 contrast — well
above AA threshold for both small text and uppercase tracking-wider
mid-weight type.

`.text-placeholder` (which uses `/40`) stays as-is because the audit
classified it as the italic empty-state pattern where lower contrast
is intentional and the surrounding context makes the meaning clear.

### 5. FormError primitive

New file `src/lib/ui/primitives/FormError.svelte`:

```svelte
<!-- src/lib/ui/primitives/FormError.svelte -->
<script lang="ts">
  let { message }: { message: string | null | undefined } = $props();
</script>

{#if message}
  <p role="alert" aria-live="polite" class="text-ochre text-sm">{message}</p>
{/if}
```

The `{#if message}` lives inside the primitive so consumers drop the
outer `{#if error}` guard. `role="alert"` plus `aria-live="polite"`
means screen readers announce the message when it appears without
interrupting the user mid-utterance. (`assertive` would interrupt;
form errors don't warrant that urgency.)

Consumers to migrate (replace `{#if error}<p class="text-ochre text-sm">{error}</p>{/if}` patterns):

- `src/lib/ui/NewRecipeDialog.svelte`
- `src/lib/ui/OutcomeForm.svelte`
- `src/lib/ui/cook/EndCookDialog.svelte`
- `src/lib/ui/ConfirmDeleteDialog.svelte`
- `src/lib/ui/EditVariablesDialog.svelte`
- `src/lib/ui/BatchEditor.svelte`
- `src/lib/ui/MergePicker.svelte`

Each consumer adds `import FormError from '$lib/ui/primitives/FormError.svelte';` and renders `<FormError message={error} />` in place of the inline pattern.

### 6. Per-route titles

Each route page gains a `<svelte:head><title>...</title></svelte:head>`
block at the top of its template. Format: most-specific-thing
first, then the recipe name (for nested routes), with the brand name
omitted (the browser tab will only show two segments before
truncating; keeping it terse helps screen readers too).

Concrete mapping:

| Route | Title expression |
|---|---|
| `/` | `"Better Batch"` |
| `/recipes/[id]` | `"{recipe.name}"` |
| `/recipes/[id]/new-batch` | `"New batch · {recipe.name}"` |
| `/recipes/[id]/batches/[batchId]/edit` | `"Edit {batch.label} · {recipe.name}"` |
| `/recipes/[id]/batches/[batchId]/cook` | `"Cook {batch.label} · {recipe.name}"` |
| `/recipes/[id]/compare` | `"Compare · {recipe.name}"` |
| `/recipes/[id]/merge` | `"Merge · {recipe.name}"` |

For routes that don't have the recipe loaded synchronously (compare,
merge, etc.), use whatever shape the existing data fetch provides; the
title can be `"Compare batches"` if recipe context isn't readily
available without restructuring the load.

### Layout `<main>` wrapper

If `src/routes/+layout.svelte` does not already wrap the route content
in `<main>...</main>`, add one. The Dialog inert effect targets this
wrapper. If a `<main>` already exists, reuse it.

## Testing

This is a primarily visual/structural change. No new unit or e2e
tests are added. Validation:

- **Pipeline:** `bun run typecheck && bun run lint && bun test && bun run e2e` must stay green across every commit.
- **Manual a11y spot checks:**
  1. Open each dialog (NewRecipe, EditVariables, EndCook, ConfirmDelete, OutcomeForm, PasteRecipe, Inconsistency, CookQuickNote). Verify:
     - Tab cannot move focus outside the dialog.
     - Shift+Tab from the first focusable wraps to the last (handled automatically by `inert`).
     - Escape closes the dialog and focus returns to the trigger element.
  2. Tab through the recipe list page, recipe detail, batch editor, and cook view. Every button and link should show a visible focus ring.
  3. Inspect computed style of `.text-caption` and `.text-kicker` headings; confirm they read as the expected darker shade.
  4. Trigger a form error (e.g. submit empty NewRecipeDialog). With a screen reader running (VoiceOver on macOS, NVDA on Windows), confirm the error is announced.
  5. Open each route in a new tab. Verify the browser tab title is meaningful.
